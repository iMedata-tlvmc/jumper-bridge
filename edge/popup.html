2. Settings

Used to build OpenPatientRecord's deep link (not present in the signal URL)
Side panel shows Gecko beside the IE-mode Chameleon tab. Chromium can only open it from a real click, so open it once here — after that the מחלקות transition keeps it in sync. If it is closed when מחלקות fires, we fall back to focusing the Gecko tab.
Shared-session mode is the default and opens the correct patient without the false alert or another login. It requires Edge Enterprise Mode cookie-sharing rules for .CHAMELEONAUTH and ASP.NET_SessionId. Plain URL mode is a degraded fallback: a spurious "מטופל/ת לא נמצא/ה במערכת" alert fires on every open and must be dismissed, the whole Chameleon shell reloads (up to ~10s in measured traces, losing app state), the session-sensitive flow may require another login, and it does not cover מחלקות detection. The alert is a server-side login.asp bug that cannot be fixed from the extension — see docs/decisions.md.
Extension mode fetches only Chameleon's authenticated shell and same-origin resources referenced by it. It does not read or store cookie values. Native mode remains available only as a temporary fallback.
